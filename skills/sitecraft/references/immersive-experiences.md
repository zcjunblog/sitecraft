# 沉浸式表达：让访问者进入内容

新建或整体重做官网默认读取并实施，不要求用户再次指定沉浸式。沉浸是一种组织空间、注意力和观看进程的方法，具体风格由主题决定。用户明确的其他方向、忠实复刻与局部修改优先按范围执行。通用的动效、控件、视觉和发布要求仍分别按现有参考执行。

## 先明确沉浸在什么里

从具体主题确定空间或观看关系：进入一个世界、近看一件作品、体验某个过程，或沿一段故事前进。写清场景承载什么内容、访问者怎样继续、主要操作在哪里。全屏只是可选手法；一幅大图加口号，尚未建立这样的关系。

- 先按 [design-playbook.md](design-playbook.md) 决定主任务。参观、票价、预约、报价或下载是关键任务时，保留可直接到达的内容与入口；只把次要详情收进面板，不把核心业务都藏到弹窗。
- 用符合主题的真实影像、原创图形、产品交互或排字建立空间。既有品牌、原作色彩和用户参考优先；明亮、平面、安静的方案同样可以沉浸。
- 颜色、字体、章节数和技术随内容确定。暗蓝暖灯、细宋体、人物背影、三段全屏等只是一种组合，不从上一项目自动继承。无需粒子、声音、3D 或重型库来证明沉浸。

## 把场景和界面作为一幅构图

先看实际素材的视觉重心、光源、可用文字区与手机裁切，再放标题和操作。画面可以承担主要面积，字标与导航的尺度由识别和使用决定；边框、底板或卡片有用途时保留，不让无关的外层包装切断场景。

需要生图时，提示词说明环境、主体位置、景深、光线和供真实 DOM 使用的文字预留区。整张页面不能烧进图片，正文、按钮、准确 Logo 与必要信息保持可选择、可访问。生成素材先看图再用；仅为视觉氛围的角色或场景不能冒充真实设施、产品和服务证据。

标题、导航和 CTA 随当前画面检查可读性。文字区可以使用局部渐暗、浅色衬底或另行排版，不必把全画面压暗。特别检查切换后的白色幕布、窗户、天空等亮区，以及动态光影最亮时的前景对比。

## 用内容决定观看进程

每一段应带来新的内容、视角或可执行动作，再决定连续长画面、章节、横向作品切换或局部展示。章节数从内容得出，不为凑整重复口号。一个短而完整的场景也能成立。

优先保留原生滚动与清楚的继续入口；导航、锚点、键盘和浏览器返回应正常。全屏段落使用能容纳内容的最小高度，容许小屏、放大文字和横屏继续滚动，不用固定视口高度裁掉正文、按钮或关闭入口。

对重要路径分别设计：首次进入、直接打开某章节、前进与后退、快速反向、关闭浮层后返回。背景、标题、章节标记与当前可操作内容应同步；转场期间也不能出现未知目的的空屏或过期控件。

## 三种动态各有作用

按 [motion-and-controls.md](motion-and-controls.md) 分别实现与取证：

| 层次 | 在沉浸场景中的设计方式 |
| --- | --- |
| 场景 Motion | 有目的的镜头、前后景关系或内容编排，运动让人感知空间或关注点；不只移动一整张图跟随鼠标 |
| 连续转场 | 背景、标题、章节与实际面板有协调的进退节奏；快速反向从当前状态衔接，不积累队列 |
| 动态光影 | 变化来自画面中的光源、表面或交互，强度与色温匹配主题；图片里画好的灯光不是动态效果 |

手机和窄窗采用合适的非指针表现，可减少层数、位移和模糊；不能把全部动态绑定在 hover、精细指针或桌面断点。长时间循环提供易找的暂停/继续方式，隐藏页面与不活跃场景暂停；系统减少动态偏好采用稳定可读的回退。必要信息不依赖动画结束。声音由明确操作开启，不添加假开关。

浮层转场遵守原生 dialog 的顶层与焦点范围。若列表退场需要副本或临时图层，应放在正确的弹层内部、不可交互，结束后清理；挂到 body 后即使 z-index 很大也可能落到顶层弹窗背后。过滤后当前控件被移除或隐藏时，将焦点交给仍可见的合理入口。

## 每个比例重新取景

桌面宽图、手机竖图和中间宽度分别检查。根据主体位置设焦点、提供裁切衍生图或调整图文位置，而非统一居中后只在手机补救。平板和桌面侧栏预览也可能裁掉人物、作品或操作；必要时用不同于手机的焦点。

每个场景单独复核标题、人物/作品、入口和导航的关系；换了一张更亮的图，上一场景的遮罩不一定仍适用。手机需要时重新编排，不把桌面标题等比缩小，也不让固定导航挡住正文。

## 先保证打开，再延续空间

首屏只优先加载当前关键素材；后续场景按浏览进度或实际切换意图准备，切换前确保图像可显示，等待期间保留可理解的画面与反馈。直接进入后续章节时加载对应素材，不能假设所有人都从首页开始。

按实际尺寸压缩，检查手机资源选择与桌面清晰度。素材、脚本与装饰都服从 [static-release.md](static-release.md) 的最终包和性能验证；慢设备减少表现成本，核心内容与操作保持可用。静态 HTML 不需要为了沉浸引入常驻服务。

## 用真实画面收尾

除 [visual-review.md](visual-review.md) 的通用检查，再核对以下本方案实际存在的状态：

- 代表性场景的桌面、手机、中间宽度画面；确认关键主体保留、主要任务可达、亮区与动态光照下文字仍清楚。
- 场景切换的中间帧、结束态和快速反向；章节标记、图像与文字一致。稳定验收图与过程采样分开命名，避免把尚未完成的叠化当成最终外观。
- 浮层进退、过滤退场、焦点与滚动恢复；暂停/继续、后台暂停和减少动态效果。
- 最终包的首屏与后续图片请求，避免进入首页就下载全部高分辨率场景，也避免未准备好图片时切成空白。

保留观察与修正证据即可，不增加用户逐段审批。不以静态截图、脚本通过或加载很快承诺动画流畅度，也不把某一次成品变成后续主题的统一模板。
