# 实际画面的验收

审美判断必须看渲染后的图。DOM 测量、自动评分、构建通过和静态代码阅读都不能替代截图。

新建或整体重做的首屏按 [参考到成品的视觉检查](executable-design-assets.md) 生成并排对照，逐项保留两端构图、中文排字、主体裁切、光线材质、主要行动与手机重排的观察。对照绑定参考阶段的设计计划和本次真实截图；发现问题必须保留 ID、修复前后图及复看结果。下文的整页和状态检查继续执行，不能用首屏对照代替。

按 [visual-selection.md](visual-selection.md) 评审原始任务、真实画面与相关外部参考，暂时放下作者的自我评价。[visual-benchmarks.md](visual-benchmarks.md) 用于对照素材、尺度和排字的完成度；[visual-cases.md](visual-cases.md) 保留正反反馈与边界。分别判断任务是否清楚、视觉是否成立；用户曾认可某案例，不代表其外观应套给当前项目。

## 准备与取证

1. 启动或复用本地 HTTP 预览。优先项目已有浏览器能力；否则可用本机已有的 Playwright 等工具。不要为截图依赖改动产品栈。
2. 等待字体与主要图片完成加载，再截图。为浏览器设置视口后读取 `innerWidth/innerHeight`，确认设置真正生效；浏览器外窗尺寸不一定是内容视口。
3. 至少查看一个桌面宽度和一个手机宽度，建议从 1440×900、390×844 开始；再在 360px 窄屏或布局断点附近检查。尺寸是起点，用户目标设备优先。
4. 保存首屏与整页截图，打开图片亲自看；长页可分段查看，不能只把数千像素的整图缩小扫过。对菜单、下拉选项面板、弹层或主题等实际存在的重要状态补充截图；下拉框闭合的截图不能替代选项面板截图。
5. 外观验收图确认目标菜单或弹窗仍然打开，并等待该次有限过渡进入稳定态；动画过程采样另行标记，不把退出中的空白画面当成手机验收。改过的区域重新截图。局部修复只需重验受影响的视口与状态，不无理由重复整套测试。

截图文件名标明视口与状态，放在任务约定的预览目录或临时目录；不要默认提交到仓库或把个人数据放进公开截图。工具对输出目录有限制时使用允许的位置。

工具连接失败先尝试可用替代方案，不要假定浏览器不可用。确实无法渲染时，说明尝试、可运行入口和未验证范围；不能把截图计划写成已完成。

## 先修可读与可用

以下问题发现即修，不能用“极简”解释：

- 文字、图标与背景融为一体，包括主按钮、浅色次按钮、图上文字、悬浮控件。检查计算后的颜色、透明度、叠层与实际图像，不只查 CSS 变量。
- 正文为追求精致而缩得难读；手机上需要眯眼的小字承担了核心信息；文本被裁切、遮挡或断成孤字。
- 内容横向溢出；布局依靠 `overflow-x:hidden`、固定高裁切或禁用缩放掩盖错误。
- Sticky 顶栏遮住锚点或标题；菜单、弹层在手机屏幕外；长内容无法滚动关闭。
- CTA 无实际动作、链接指向 `#` 却假装完成业务、表单提交后假称已发送。缺后台时明确提供可用联系方式或可辨识的演示状态。
- 正文只有脚本执行或入场动画后才可见，脚本失败整页空白。
- 下拉仅美化触发框，展开面板出现未经选择的系统样式；自定义选项点得动但无法键盘操作、提交值未同步，或在 dialog 内被遮挡。

常规文本对比度以 4.5:1、大字以 3:1 为常用检查基准；必要的边界和图标亦须可辨。达标仍需看实际字号、字重和背景纹理。大字判断以真实大小和字重为依据，不能任意把小字算作大字。

## 再修视觉质量

### 整页视觉修订：首次交付的一部分

首轮实现后，从顶部到页脚查看真实桌面与手机画面，以当前主题和主要任务为准逐段完成一轮内部修订。不是强制再换一套风格，也不是让用户先审稿；有可见问题才返工，没有问题不为凑修改而添加装饰。

每段用简短工作记录回答：**提供了什么新信息或动作 → 为何采用这个尺度与结构 → 实际画面里是否成立**。找出最缺少依据的区域，先修内容、构图或素材，再看细节。改后查看该区域与相邻区块，确认整页节奏连贯。

将代表性画面与所选参考一同看，明确主图质感、主体尺度、中文排字、信息密度和整页节奏的实际差距。任务更清楚或两版中较好的一版，也可能视觉完成度不足；两版都落入同一种无依据的包装时可以均不采纳，回到构图与素材。比较不得变成复制参考品牌，或给全站套用它的深浅底色。

- **品牌表达与业务说明各司其职**：少量品牌句可以建立情绪，价格、交付、规则和养护等用直接、具体的语言。若抒情标题只是在改写下方功能名，减少这一层。栏目不足以成立就合并或省略，不为凑三列编造内容。
- **结构由信息关系决定**：需要比较的独立对象可以等列，过程可连续呈现，时间/费用可做紧凑清单。三列、细线、FAQ、卡片和小英文并非禁用；缺少实际理由时，不将它们顺次拼成每个行业相同的下半页。基础信息应直接可读，真正需要按问题展开的内容才用折叠。
- **视觉要求必须可见**：“简约”落实为减少竞争层级与无用标签；“大气”落实为清楚的主焦点、足够的主体尺度和完整的留白关系；“浪漫”可由花材、色彩、字形与材质共同表达。数值和表达随项目变化，不把白底、粗体或爱心变成所有网站的规定。
- **主题词不等于符号清单**：主视觉缩小看整体轮廓、色块与第一联想，再看细节。若形态产生明显偏离当前主题的熟悉符号联想，调整构图或换素材；不靠增加文字解释掩盖。用户指出联想不适合时，优先更换负责该问题的视觉元素。
- **声明与装饰不过度分散**：演示、来源和业务边界保持清楚，但不在每个区块重复堆叠。辅助英文、编号、标语必须有具体作用，不能凭它们把缺少信息的空段落包装成设计。

保留少量“问题区域 → 实际修改 → 改后截图”证据。功能、体积和加载通过仍分别记录，不能作为无需视觉修订的理由，也不以主观分数保证用户一定满意。

### 构图检查与返工条件

品牌层另作一次检查：背景/强调色、字标与字体、标题构图、图像语言是否有共同内容依据。保存正常首屏和内部去图对照，检查小字标/站标；主图恢复后再交付。若图像拿走只剩跨行业通用包装，或标题、标志与插画互不关联，先修品牌系统。去图检查不要求牺牲成熟控件、用户明确 CI 或忠实复刻；不能以换颜色或新增动效代替品牌修正。

核对表达方式是否支持当前任务，而非沿用上一项目的风格。选择沉浸式时，再按 [immersive-experiences.md](immersive-experiences.md) 检查观看进程、核心业务入口、中间宽度取景、亮区文字与场景切换；其他页面不为通过这项检查改成全屏叙事。

新建或整体重做时，在首屏阶段就检查以下问题；交付前结合整页节奏再看一次。每项依据实际截图与当前任务作判断，不以任意的面积比例、图片数量或美观总分替代判断。

| 检查 | 需要返工的可见证据 | 优先修改 |
| --- | --- | --- |
| 页面角色 | 用户要挑选或操作，首屏却主要是口号和与任务无关的介绍；策展页的大图没有主题或观看顺序 | 重排内容与入口；明确工具、策展或品牌叙事的主次 |
| 视觉方向 | 设计依据只有配色形容词；画面没有对应的内容关系或明确焦点 | 落实主图、排字、密度与对齐的具体决定，不先加特效 |
| 素材与文字 | 主图无法支撑主题、关键主体裁切错误；泛化口号和英文编号占据显著空间却没有信息作用 | 换片、重裁、改具体文案或删去无用装饰；混合题材图库不强求同色 |
| 结构与节奏 | 所有内容被拆成相同卡片；空白和重复栏目拖延任务；手机主要内容被装饰推走 | 合并或删区块，调整尺寸关系与顺序；有用途的卡片保留 |

出现上述问题，不能用“按钮已通”“没有溢出”“截图已生成”作为交付理由。先修改负责该问题的结构、素材或文字，重新截图查看受影响区域；更换渐变、圆角或补 hover 不能替代构图修正。没有可见问题时无需为凑报告而改版；不要覆盖用户明确指定的布局、参考和风格。

在工作记录中保留简短证据：**截图路径与视口/状态 → 观察到的区域 → 保留或修改的理由 → 修改后的截图**。例如“手机首屏只有标题与精选，图库入口在屏外；压缩介绍并前移筛选与首批图片，重看手机首屏”。这是视觉判断记录，不要求产出长审计文档或向用户逐项求批。

视觉、交互、资源与速度各自报告结果。视觉方向仍不成立或无法查看实际画面时，如实说明未解决项，不能以其他检查通过给它背书；无法继续改善时交代具体限制，不无止境堆装饰或声称审美已获认证。

按截图定位问题，给出具体区域与动作，避免“还不够高级”的笼统反馈：

| 维度 | 在图片上寻找 | 有效修改 |
| --- | --- | --- |
| 焦点 | 第一眼是否知道看哪里、页面干什么 | 减少竞争元素，调整主次尺度与位置 |
| 构图 | 主图、标题、操作是否互相支持 | 调列宽、裁切、内容顺序和视觉重心 |
| 节奏 | 下滑是否全是同样的卡片或空白 | 按内容改变区块结构，删重复信息 |
| 文字 | 中文断行、行距、段宽、信息密度 | 改真实字体与排版，不只缩放容器 |
| 细节 | 按钮文字基线、图标笔画、图像接缝 | 统一控件规则与素材处理 |
| 一致性 | 图片光线、圆角、颜色与边框是否属于同一系统 | 收敛到当前视觉概念，去掉无关手法 |
| 手机 | 是否经过重新编排，主操作是否可达 | 调整顺序与裁切，保持正文尺寸和自然滚动 |

若连续修改同一问题仍不成立，回到构图或素材选择，不继续堆局部装饰。

## 验证真实操作与性能

测试该页面实际存在的主要操作：导航、菜单、弹层关闭、表单反馈、键盘焦点与主要 CTA。无需为纯样式变化编写复述 CSS 的单元测试；有行为修改时使用与风险相称的项目检查。

按 [motion-and-controls.md](motion-and-controls.md) 检查实际使用的控件状态。下拉必须通过真实点击或键盘打开后检查选项面板，再验证选择与提交；测试代码直接设置值不算展开态验证。对原生系统面板无法截图的情况如实标记，不声称完整视觉一致。

实际观察主要过渡的进场、退场、快速中断，以及 `prefers-reduced-motion`；反馈应及时，不留不可见但仍挡点击的遮罩。若关闭清理依赖动画结束事件，还要验证零时长路径。静态截图只证明画面，不证明动画过程、流畅度或性能。

按动效契约分别记录 **场景 Motion / 连续转场 / 动态光影** 的触发、连续过程和结果。查看中间帧、快速切换与关闭、桌面/手机/预览窄窗、离屏暂停和减少动态效果。静态插画、渐变蒙层、hover 或单个弹窗不足以同时通过三项。只有起止态或功能检查时，动态质量仍未验证；不因文件小、LCP 低或截图漂亮而放行。

检查新增 UI 是否引入了未获明确要求的 Emoji；默认使用一致的 SVG 或项目图标系统，用户明确指定 Emoji 风格时沿用该例外，并保留用户原文、引用与普通标点。光影检查层级、统一光源、背景变化后的可读性和无模糊回退；平面风格无阴影并不算缺陷。

检查图片是否成功、控制台有无相关错误，网络里有无不必要的大图、远程字体或阻塞脚本。关键大图不要 lazy-load，非首屏图像按需加载，预留尺寸避免明显跳动。仅本地截图或字节统计不能证明线上“秒开”。

按 [static-release.md](static-release.md) 检查实际交付物。部署包从干净的解压目录复核；离线单文件用最终 HTML 验证直开和资源自包含。

## 交付证据

在用户看得到的结果旁，简短说明设计方向、可打开的页面或文件、代表性截图、实际查看的视口与主要操作，以及仍未验证的限制。

允许用户有不同审美；证据说明做过哪些检查，不伪装成“必然好看”的客观认证。
