# 从可见参考到方案选择

用于新建、整体重做或视觉方向未确定的项目。局部修复、忠实复刻和用户已认可的设计按原范围执行。这里改进的是选方案与视觉修订的过程，不把某套外观称为客观正确答案。

## 先看图，再形成方向

优先查看当前项目素材、用户参考和已有成品。新品牌或没有成立视觉系统的整体重做，默认先查看少量与任务相关的真实品牌页面或设计作品，再形成方向；由执行者查找，不转交给用户补参考。参考不是配色名称清单：指出可借鉴的主体尺度、图文关系、阅读顺序或材质，以及不适用的部分。

按 [visual-benchmarks.md](visual-benchmarks.md) 打开相关外部实图；没有匹配项目时主动查看其他实际作品，不按行业机械分配这些品牌。通常一至三个相关参考足够；存在方向分歧时再看不同的组织方式。搜索摘要、网站名清单和作者的文字解释均不算看图。已有明确参考或 CI 时以其为准，局部修复不扩大成案例搜集。看图或联网确实不可用时，使用可用的内置图和当前材料，标明参考缺口后继续可完成的工作，不编造访问记录。

[visual-cases.md](visual-cases.md) 保存实际成品与用户反馈，包括花店方向匹配和三个被否定的文艺化页面。按需查看，不能只看有利评价，也不能把曾被否定的图继续当作“审美通过”。

在内部用一段话锁定方向：**主任务与内容证据 → 主体和空间关系 → 字体/颜色/材质怎样支持它 → 首屏的主要操作**。落实到画面选择，不以“高级、简约、沉浸”三个词代替。

## 识别是否又落回同一套文艺包装

暂拟品牌、配色、排字与文案从当前业务重新确定。把方向与近期实际页面及失败案例并排看：若名称语感、抒情句式、底色、字体、图文框架和配图质感同时重复，而业务没有给出这些选择的依据，重新处理主视觉与排字关系。只把米白改成灰、朱红改成蓝，仍然没有改变构图。

宋体、暖色、细线或左文右图各自都可以成立。判断重复的是整套无依据的组合，不设单项黑名单，也不强制下一个项目与前一个在所有细节上不同。已有品牌、用户指定的文艺方向和连续产品系列保持相应一致性。

主视觉需要实物、空间或工艺质感时，先保证摄影、原创图像或渲染的完成度。简易 SVG、CSS 画与低细节示意能解释结构，却不能自动替代这些材质；轮廓可辨也不等于适合担当品牌主视觉。素材不足时选择能成立的排字或实际产品演示，或按现有图像能力制作并看图复核；不伪造实拍和客户案例，不自动采购。

## 有分歧时，比较小样而非整站试错

只有一句行业描述、没有成立的视觉系统，且两种构图会显著影响结果时，先做少量实际首屏小样，通常两个足够。用同一组事实与主要内容，比较不同的主体尺度、图文关系或观看方式；只换颜色与圆角不算不同方向。

小样采用能说明取舍的实际可用素材与中文排版，渲染桌面和手机。只实现必要首屏和一个主要动作，不分别开发两套完整站点或业务逻辑。将小样与选定的外部参考一同查看；比较尺度、图像完成度、排字与空间关系，不只在两份 AI 产出中选较整齐的一份。两版共同沿用失败外观时，回到素材和构图，而不是必须选出“赢家”。执行者自行取舍再扩展整站，用户不必先选方案或追加专业提示词。

已有明确参考、品牌系统或用户指定构图时，直接落实并复核，不为凑对照另做一套。用户只讨论方法时不因此创建网站。没有图像工具也可用实际内容与可运行排字小样比较，不自动采购素材或调用额外付费服务。

## 评审对象是画面

先隐藏实现过程和作者的自我评价，只用原始任务、必要事实、真实截图、相关参考及可操作入口判断。把**任务清晰度**与**视觉完成度**分别说明，再分别报告功能、动效与加载：服务对齐更清楚、技术全绿，不能证明品牌与图像的审美已经成立。

评审留下少量可复核的结论：

| 结论部分 | 应指出什么 |
| --- | --- |
| 可见位置 | 哪个视口、区块或状态，画面里的具体区域 |
| 与任务的关系 | 信息、主体、层级、素材或阅读顺序怎样支持或阻碍当前任务 |
| 取舍 | 保留哪一版或哪种关系，理由是什么；未胜出的方向在什么条件下仍可能成立 |
| 返工与复看 | 需要改的内容/构图/素材及受影响画面；没有问题时说明保留，不强行改动 |

有可用且已授权的独立评审时，给对方原始任务、画面和所用参考，不附“这版已经很好”等作者判断，也不暗示该选哪张。由执行者自行审阅时，明确是自审；换尺度看整体焦点，再看真实尺寸的文字与操作，不把同一个人的再次解释称为独立验收。评审不形成例行用户审批点。

方案选择主要看：主题是否具体、视觉主次是否有力量、素材和文字是否共同构图、必要任务是否直接可达、手机是否重新编排。按当前品牌解释取舍，不用固定图片占比、统一布局或美观总分宣布通过。

## 从首屏延续到整页

选定首屏后再扩展内容；完成整页后按 [visual-review.md](visual-review.md) 做视觉修订。确认后续区块仍使用同一内容语言，而不是又接回无依据的三列、口号、FAQ 与页脚。成熟结构有明确用途时保留。

当问题来自主体或构图时，直接改变对应选择，不靠反复改色、加英文或叠效果拖延。比较与返工只针对存在的分歧和问题；没有证据时不循环生成一整批版本。图像质量、业务细节或用户偏好仍有不确定性时，如实记录，不能保证一句话就准确猜中所有审美偏好。

## 积累可迁移的案例

只记录实际产出与真实反馈：任务和已知条件、可看的图、关键取舍、适用边界、哪些结论不能泛化。用户确认的图可以作为该案例的偏好证据，不能反推其颜色和字体适合所有品牌。

维护 Skill 时，文字决策测试只能证明规则理解。要判断首稿视觉是否改善，还需用未参与案例整理的新主题产出实际页面，再审阅截图与主要状态；报告样本和局限，不把案例数量或一次通过写成普遍成功率。
