# 动效、光影与控件状态

为当前页面建立一套相互协调的交互与空间规则。这里的数值是可调整的起点，不是所有品牌的固定外观，也不强制使用某个动画库。

## 三项交付契约：Motion、转场、光影分别成立

新建官网默认自主设计下列三项，表达和强度随内容与品牌调整；不把所有品牌做成相同的发光模板。已有项目的局部修复不因此扩大范围。用户明确无动画、无阴影、保留静态参考等要求，以及真实的减少动态效果设置优先。

| 项目 | 应有的实际体验 | 不能替代它的内容 |
| --- | --- | --- |
| 场景 Motion | 首屏或关键内容有可感知的编排、分层运动或有意的动态节奏；正文默认可读 | 单个标题轻移、按钮 hover、小弹窗开关、仅随鼠标移动整张图 |
| 连续转场 | 页面实际存在的筛选、展开、切换、菜单与浮层有起止关系，内容/位置/尺寸变化衔接自然 | 直接改 hidden/display、只有颜色变化、只测最终选中值 |
| 动态光影 | 与场景光源、表面或交互有关的光照/反射/高光变化；强度克制且仍能阅读 | 图片内已画好的阳光、静态渐变或投影、无关光斑 |

把每项的目标元素、触发、变化、时序、反向操作、移动端适配与低动态回退简短记入内部工作笔记。用户已经提出的效果要求跨后续短指令保留；不能因最新一句话只提行业而丢失，也不能因要求轻量就省略效果。优先优化实现成本，必要的降级需说明具体原因。

手机/窄窗仍应看到有意设计的动态版本；可以减少位移、层数和模糊，不能仅因 `max-width` 就关闭所有表现。指针跟随只在精细指针启用时，其他设备仍需合适的非指针表现。检查实际预览宽度而非只检查 1440px 和一个手机截图。

## 动效：按状态与节奏实现

新页面在实现前简要确定：哪些状态发生变化、动画表达什么、时长与缓动如何共用、何时减少或关闭。局部修复优先沿用现有系统，不因补一个下拉框给全站加动画。

| 层次 | 页面中存在时要设计什么 | 可用起点 |
| --- | --- | --- |
| 控件反馈 | 按钮悬停/按下、选中标记、图标变化；触控不依赖 hover | 120–180ms；短距离位移、颜色或边界变化 |
| 菜单与弹层 | 打开、关闭、遮罩、焦点到达与返回 | 180–260ms；4–8px 位移与透明度，进出方向有关系 |
| 内容切换 | 标签页、折叠内容、结果反馈；尺寸变化不推得页面跳动 | 160–240ms；避免重播整页入场 |
| 场景表达 | 首屏编排、图像分层、缓慢光影等，与视觉概念和内容相关，桌面/手机均可感知 | 可从 400–900ms 编排开始；按内容另定，不强制循环 |

- 时间与 easing 写为少量命名令牌，避免每个组件随意设置。展开可平稳减速，关闭可稍短；不把所有运动都套弹簧、弹跳或统一 `ease`。
- 只过渡实际需要的属性，避免 `transition: all`。优先 transform、opacity；颜色等小范围过渡适度使用。不要持续重算大面积模糊、阴影或布局。
- 触发后立即有可见反馈，键盘焦点立即可辨；不等动画结束才允许操作，也不为展示动画延迟真实业务。
- 快速连点、反向操作和切换途中能取消或回到合法状态；不积累动画队列。弹窗退出期间仍管理好焦点与页面滚动，真正关闭后恢复到触发入口。
- 支持 `prefers-reduced-motion`：关闭装饰漂浮、视差和大幅移动，保留必要的即时状态变化。用户明确要求静态时尊重要求，不为满足清单添加运动。
- 若实现等待 `animationend` / `transitionend` 才关闭或清理，要处理零时长、动画取消、元素移除等路径；不能在减少动态效果时卡住浮层。
- 入场动画失败或脚本未运行时正文默认可见；滚动不劫持、锚点不被动画阻断。大段内容和每个卡片不重复做同一套 reveal。
- CSS 足够时使用 CSS。项目已有动画库可复用；不要为了证明有 Motion 而新增重型依赖。
- 有尺寸或位置变化的筛选、列表与展开可采用 FLIP、受控高度或合适的布局补间。新目标从当前视觉状态继续，取消过期动画；先隐藏旧内容再淡入新内容不能冒充位置连续。退出中的内容不可继续接收点击或留在键盘焦点路径；结束后恢复自动尺寸，避免定高裁切。
- 光影和场景循环离屏、标签页隐藏时暂停；减少动态效果时即时收敛到稳定画面。不要用常驻高频 JS 循环重排整个页面；静态内容与交互不能依赖装饰运动完成才可用。

例如，将两种用途分开，而不是到处写随机时长：

```css
:root {
  --motion-feedback: 150ms;
  --motion-panel: 220ms;
  --ease-settle: cubic-bezier(.2, .7, .2, 1);
}
.action {
  transition: transform var(--motion-feedback) var(--ease-settle),
              background-color var(--motion-feedback) linear;
}
@media (hover: hover) and (pointer: fine) {
  .action:hover { transform: translateY(-2px); }
}
.action:active { transform: translateY(0); }
@media (prefers-reduced-motion: reduce) {
  .action { transition: none; transform: none; }
}
```

示例不替代组件的前景色、键盘焦点与禁用逻辑，也不代表所有按钮都应上浮。

## 光影：先定义空间关系

先决定画面是平面、柔和实体、玻璃还是其他材质，再定义页面底层、普通内容与悬浮面板的区别。

- 平面风格可以用留白、边界与色面建立层级，不强行加投影；需要动态光影时，可用与场景一致的局部柔光或控件表面高光，避免整页发光。
- 使用阴影时统一光源方向、色温、软硬和高度关系；普通卡片不应比模态窗口更像浮在上面。
- 玻璃需要背后真正有内容层次，并有足够的文字对比；模糊失效时仍提供清晰表面。图片上的字以实际裁切与背景验证，不能假设黑色蒙层一定足够。
- 流光、边缘高光、指针视差等可集中用于一个有意义的视觉焦点。定义移动端适配、减少动态效果、离屏暂停与成本边界；正常移动端不一律退成静态，真实减少动态效果设置才采用稳定回退。
- 不用多层发光边框、彩色光斑与颗粒遮掩空洞内容。光影系统与照片光线、控件表面协调。

## 控件：设计真实存在的状态

为页面实际使用的控件检查下表。不是每个控件都有全部状态，不为验收清单引入新业务。

| 状态 | 检查点 |
| --- | --- |
| 默认 | 字体、前景色、尺寸、图标重量、基线与标签对应 |
| 悬停/按下 | 反馈明显但克制；触控上无粘住的 hover，布局不位移 |
| 键盘聚焦 | 语义焦点令牌，与当前底色对比明确；不粗暴清掉 outline |
| 展开 | 面板边界、对齐、层级、宽高、滚动与视口碰撞 |
| 选中 | 当前值与导航焦点可区分，必要时使用勾选等辅助标记 |
| 禁用 | 视觉与真实不可操作状态一致；不要仅变灰但仍可点击 |
| 错误 | 错误关联具体字段，有可读文字，不只改变颜色 |
| 加载/空态 | 仅在真实存在时设计；防止重复提交，预留尺寸，不虚报成功 |

焦点、选中、危险操作、悬浮表面分别用语义令牌，不把原型里随手写的橙色焦点框或系统蓝色选中条带到所有品牌。焦点样式可以使用高对比的辅助色，但必须是有意选择且与全站一致；不用隐藏焦点来追求整洁。

## 下拉选择：明确原生或自定义策略

**收起的选择框和展开后的选项面板是两个都要验收的表面。** 给 `<select>` 加圆角、背景和 `appearance`，不等于已经统一选项面板。

- 桌面端要求与品牌一致的面板、选项、选中标记或动画时，优先复用项目中成熟、可访问的选择组件；没有时采用完整的 select-only combobox / listbox 模式。不要仅画一个可点击的 div 列表。
- 移动端可有意保留原生选择器，以获得系统触控和辅助功能；这不是未完成的桌面组件。明确两端策略，不用设备名称猜测，按真实交互与视口验证。
- 简单表单可保留原生控件，尤其用户明确要求原生体验时；需接受并说明系统面板的边界，不承诺普通 CSS 能在各系统完全统一。不要为了品牌视觉牺牲语义、触控和键盘能力。

### 自定义选择器的最小契约

1. **标签与语义**：有可访问名称、当前值、展开状态及面板关联；选项具有明确选中状态。选择一种一致的焦点模型，不混用两套相互冲突的 ARIA 模式。
2. **键盘**：能以键盘打开、上下移动、确认选择、Escape 关闭并返回触发入口；Tab 正常离开，不把选择器变成焦点陷阱。按所选模式处理 Home/End 与长列表文字查找，支持中文输入场景。
3. **表单**：视觉值、实际提交值与组件状态只有一个来源；服务选项动态更新后仍一致。验证 change、reset、required 与禁用行为中实际使用的部分，不留两个被重复读出的控件。
4. **面板**：锚定触发框，宽度足够容纳内容；长列表限高可滚动，打开时当前选项可见。临近屏幕底部时向上展开或调整位置；不被父容器裁切。
5. **弹层关系**：选择器放在模态对话框中时，应在正确的顶层与焦点范围内呈现。不要仅用巨大 z-index 或把面板随意挂到 body，造成被原生 dialog 遮挡或失去焦点。
6. **选项外观**：行高、内边距、圆角、悬停色、选中底色、标记与分隔线沿用当前视觉系统。区分“键盘正在查看”与“已提交的选择”；长文字可读，触控目标足够。
7. **关闭与运动**：选择、外部点击、Escape 和焦点离开按模式正确收起，保留已经确认的值；打开关闭的短过渡不阻塞交互，减少动态效果时即时完成。嵌套浮层把 Escape 交给当前最上层的已打开对象：下拉打开时先关下拉，下拉已关闭时不能继续吞掉 Escape、导致父弹窗无法退出；同一次按键也不能误关两层。

不能为了统一一张截图，破坏 native select 的提交或验证，也不能只补 ARIA 属性就声称自定义组件已经可访问。

## 验证必须真的触发

- 下拉：实际点击或键盘打开，查看并保存展开面板；测试鼠标选择与键盘选择，再核对表单真实值。`selectOption()` 等直接赋值 API 只能证明值更新，不能证明面板外观。
- 浮层：检查打开、关闭、焦点恢复、滚动恢复、快速反向操作，以及减少动态效果。在弹窗内打开下拉后，连续按两次 Escape，应先关闭下拉、再关闭父弹窗，并分别恢复正确焦点；不能仅测试关闭按钮。原生系统弹出菜单若工具无法截取，明确此状态未视觉验证，不用一个仿制 DOM 截图冒充。
- 动效：分别观察场景 Motion、转场、动态光影，记录录屏或带时间点的连续画面/状态；采样中间过程，而非只保存起止两张。实际触发进场、退场、快速反向、重复切换、动态设置变更与焦点/滚动恢复。静态截图或 CSS 声明不能证明过程流畅，加载测速不能证明动画帧率；未测不报 60fps。
- 首屏效果要在实际桌面、手机和预览窄窗查看。滚动进入主要区块、切换筛选、打开/关闭菜单和弹层，分别确认连续性；既有功能测试全绿也不能豁免缺失的效果。工具无法观察动态过程时，报告未验证项而非宣称完整交付。
- 仅更新 Skill 时，用临时样例或已有证据验证规则，不自动改动或发布用户的网站。
